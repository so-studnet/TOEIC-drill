# TOEIC-drill 要件定義書

- 文書ステータス: ドラフト(ユーザー確認待ち)
- 作成日: 2026-07-31
- 対象リポジトリ名(予定): `TOEIC-drill`

## 1. 背景・目的

TOEIC(主にリーディングセクション)の問題を繰り返し演習できる、個人学習用のWebアプリケーションを開発する。
既存の演習サイト [過去問ドットコム](https://toeic.kakomonn.com/) の使い勝手を参考にしつつ、自分専用の問題データ・学習記録を管理できるアプリを作る。

## 2. 参考サービス分析(過去問ドットコム)

サイト調査により、以下の機能構成を確認した。

| 機能 | 内容 |
|---|---|
| 出題形式 | 1問1答形式。回答後すぐに正誤・解説を表示 |
| Part別出題 | Part1〜6、単語・熟語などカテゴリ別に選択して出題 |
| ランダム出題 | 範囲内からランダムに出題 |
| 続きから出題 | 前回の途中から再開可能 |
| 付箋メモ | 気になる問題にブックマークを付けられる |
| 解答履歴 | 過去の回答結果を確認できる |
| 誤答再出題 | 間違えた問題だけを集中的に再演習できる |
| 分析機能 | 解答傾向の分析(ログイン後) |

本アプリはこの構成を参考にしつつ、後述のスコープに従いMVPを定義する。

## 3. スコープ

### 3.1 MVP(初回リリース)に含む機能

- **出題範囲**: リーディングセクションのみ(Part5・Part6・Part7)
  - リスニング(Part1〜4)は音声ファイル管理が必要となるため対象外
- **出題機能**
  - Part別出題(複数Partを組み合わせて選択可能。例: Part5+Part6のみ、など)
  - ランダム出題(選択範囲内からランダムに出題)
  - 続きから出題(中断・再開。出題セッションの進捗を保存)
- **解答形式**: 1問1答形式のみ(1問回答→即座に正誤判定。まとめて採点する模試形式はMVP対象外)
- **解説表示**: 解説データがある問題は表示する。解説なしの問題があっても許容する(解説は任意項目)
- **復習・振り返り機能**: 間違えた問題の自動ブックマーク、およびブックマークした問題だけを集めて再出題するモード
- **問題データ取込機能**: 手動でファイルをアップロードして問題データを登録する
  - ファイル形式(CSV/Excel/TSV等)の詳細仕様は本要件定義の対象外とし、別途「問題データ設計」フェーズで詳細設計する
- **問題データの編集・削除機能**: 登録済み問題の全項目(問題文・選択肢・正解・解説・Part等)を編集できる。削除は個別削除、およびPart単位での一括削除に対応する
- **利用者**: 自分専用のシングルユーザー利用。ログイン・会員登録機能はMVPでは不要

### 3.2 将来スコープ(MVP外・拡張候補)

以下は要件として明確化はするが、MVPの実装対象外とする。今後のフェーズで優先度を検討する。

- リスニングセクション(Part1〜4)の追加(音声ファイル管理・再生機能)
- 複数ユーザー対応(会員登録・ログイン・ユーザーごとのデータ分離)
- 時間制限付き模試モード(本番同様の問題数・制限時間でまとめて採点)
- 正答率・苦手分野(文法項目/語彙カテゴリ等)の分析機能
- スコア推移のグラフ表示
- Web公開(Vercel等へのデプロイ)。MVPはローカル環境での動作を優先し、公開を見据えた設計とする

## 4. 利用者像

- 利用者: 開発者本人(TOEICのリーディング力向上を目的に学習する個人)
- 利用環境: 当面は自分のPC上のローカル環境。将来的にはWeb上に公開し、どこからでもアクセスできるようにしたい
- 利用頻度: 日常的な学習(すきま時間でのドリル演習)を想定

|---|---|---|---|

| F-14 | スコア推移グラフ | 模試モードのスコア推定値を時系列で可視化 | 将来 |

## 6. 非機能要件(方針レベル)

- **データ永続性**: 出題進捗・ブックマーク・問題データはアプリを閉じても失われず、次回起動時も参照できること
- **拡張性**: 将来のリスニング対応・複数ユーザー対応・Web公開を見据え、機能追加がしやすい構成とすること(具体的な技術選定は次工程の基本設計で決定する)
- **保守性**: 問題データの追加・更新が容易に行えること
- **動作環境**: MVPはローカル環境で動作することを優先し、Web公開を阻害しない設計とする
- 技術スタック(言語・フレームワーク・DB等)は本要件定義では確定せず、次工程「基本設計」で提案・決定する

## 7. 未確定事項・今後の設計課題

以下は要件定義の段階では扱わず、後続フェーズで検討・確定する。

- 問題データのファイル形式(CSV/Excel/TSV等)とデータ項目の詳細設計 → 「問題データ設計」フェーズ
- 技術スタック(フロントエンド/バックエンド/DB/デプロイ先)の選定 → 「基本設計」フェーズ
- 画面構成・画面遷移 → 「基本設計」フェーズ
- データベース/データ保存方式の詳細 → 「基本設計」「詳細設計」フェーズ

## 8. 開発の進め方

ウォーターフォールモデルに従い、以下の順で開発を進める。各工程完了時にユーザーに内容を確認してもらい、承認を得てから次工程へ進む。

1. 要件定義(本書) ← 今ここ
2. 基本設計(外部設計): 画面構成、技術スタック、問題データのファイル形式設計を含む
3. 詳細設計(内部設計): データベース設計、モジュール設計
4. 実装
5. テスト
6. リリース・移行(GitHubリポジトリ`TOEIC-drill`への格納を含む)
